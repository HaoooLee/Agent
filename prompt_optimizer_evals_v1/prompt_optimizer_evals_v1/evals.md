# Prompt 改写评测

评测三个问题：是否保留原意，是否补齐影响执行的关键缺口，是否改善实际回答。篇幅、标题、角色和步骤数量不直接计为提升。

## 数据与任务

目前 27 条：13 条 dev、14 条 test；22 条可执行，5 条仅评改写。原 20 条的公开输入及来源不变，新增 E21–E27 覆盖开放目标、决策标准、多任务依赖、混合材料、显式协议变更、多轮助手和事实不确定性。

- `evals.json` 保存输入、判定要求、保护项和执行配置；优化器只接收 `prompt`。
- `sources.json` 保存公开样本的固定版本和输入哈希；新增案例标为已暴露的诊断案例。
- E01/E03 是设计请求，按用户消息执行，评估设计结果；E02/E26 是已有助手指令，按系统角色执行。
- E06 的普通需求描述允许改善措辞；数据、代码、引文、协议和变量的保护项另行保留。
- 禁止无依据的事实、强制要求和额外任务；有助于目标的判断标准、依赖、必要默认值和验证方式可以补充。

全部案例已在本次讨论中检查。dev/test 保留用于组织迭代，不能据此声称存在未暴露的独立验证集。针对这些案例调参后，应另准备新样本检验泛化。

## 判定与证据

先判断保真，再比较建设性改写与下游效果。裁判接收原始需求、匿名两侧提示词、实际回答、执行材料、变量填充值和机械检查结果。

JSON 检查要求完整裸 JSON，拒绝代码围栏、重复键和非标准常量；固定 schema 检查精确字段与类型。项目数、词数、禁用词和指定材料使用轻量检查；语言、事实和充分性等仍需语义判定。这不是官方 IFEval 分数。

机械检查覆盖错误的保真结论。裁判偏好与执行硬约束冲突时，保留原始判断，修正矛盾偏好并标记复核。证据片段须属于指定一侧的实际材料。保真失败单独计数，下游偏好仅纳入两侧均保真的案例。

`provisional_*` 保存含待复核项的暂定偏好，普通偏好计数排除待复核项。完整矩阵交换左右顺序重判，最终计数要求两次判定均成功、无需复核且结论一致；违例说明的措辞变化不算顺序偏差。未标记复核不代表人工已确认。

空响应、截断和调用失败保留为错误，不回退原文伪装成功。记录案例、提示词和执行配置哈希、模型 ID、调用耗时和 token 用量。输入、标注或 fixture 变化后，旧记录不可混用；结果 JSONL 使用新文件，矩阵保存运行时输入和代码快照。

## 三版本完整比较

better-prompt 原版的默认完整流程包含追问和人工确认。本矩阵的原版默认流程运行到 Lyra 后记录 `interaction_required`，不虚构用户回答或确认；没有最终自动输出时，不参与质量排名。另测明确标记的 `better_prompt_noninteractive`：取消追问、确认和说明输出，保持 Lyra→Meta 两阶段。适配版不等于原版；本矩阵不声称覆盖其全部命令路由。

矩阵评测适配版、`request/meta_prompt.md` 和 `meta_prompt_v3.md`，同时保留原输入基线。四组各执行一次，缓存同一回答供六组成对比较复用，每组以正反两种顺序判定。计划 547 次调用，默认不重试。正反判定复用执行结果，检验裁判顺序偏差；执行采样波动需另跑独立记录。

在项目根目录 `.env` 或环境中配置 `OPENAI_API_KEY`，可选 `OPENAI_BASE_URL`。`EVAL_MODEL` 指定统一模型，或分别设置 `EVAL_OPTIMIZER_MODEL`、`EVAL_EXECUTOR_MODEL`、`EVAL_JUDGE_MODEL`。`.env` 支持字面量赋值，不执行 shell 表达式，已有环境变量优先；密钥不进入快照。

以下命令在本评测目录执行：

```bash
../../.venv/bin/python -B run_evals.py validate
../../.venv/bin/python -B -m unittest -v test_evals.py
../../.venv/bin/python -B run_matrix.py --dry-run --output runs/preflight-new
../../.venv/bin/python -B run_matrix.py --output runs/comparison-new
```

`--dry-run` 冻结输入和调用计划，不调用模型；真实运行缺少密钥或模型 ID 时直接报错。已有目录不可覆盖。默认超时 60 秒、输出预算 4096 token、并行 3 个任务，可调整矩阵参数。

单独比较可使用 `run_evals.py generate/execute/compare/summary`。`generate --meta-prompt ../../meta_prompt_v3.md` 评测 v3；`--skill-directory ../../better-prompt` 保留原版交互边界，增加 `--noninteractive` 明确启用适配。

## 结果复核

查看全部调用错误、保真失败、执行硬约束失败、待复核项和顺序敏感项。核对证据，并分别报告 dev/test 与建设性增强案例。成本、延迟和质量结论须来自真实模型记录。

离线测试和 dry-run 只验证评测流程，不能证明三版本质量或选出赢家。真实结果保存在独立运行目录的 `report.json` 和逐条 JSONL 中。
